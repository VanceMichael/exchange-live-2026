# 校际连线的双地时段采集与口译接力

联络工具：把两校本地校历、双边会议室开通和口译员可用时段合成一份可执行结论。
收到的改课会增量续用，状态落在本地 JSON 里，可反复运行。

运行环境为 Node.js 22.23.4。这里的资料由本地来源模拟器提供，编号、参与方和历史业务记录全部为合成数据。

## 快速开始

```sh
npm run source     # 业务来源，默认 127.0.0.1:8700
npm run provider   # 校历与会议室演练接口，默认 127.0.0.1:8701
npm test           # 契约与行为测试（各自使用临时端口）

npm run liaison -- sync --format text          # 取数、同步校历、回读房间
npm run liaison -- plan --format text          # 窗口 / 接力 / 改约结论
npm run liaison -- teacher --school E --day 2026-11-20 --format text
```

默认状态文件是 `data/state.json`（已被忽略）。用 `--state`、`--source`、`--provider`、
`--now` 覆盖；时间相关的判断都以 `--now` 为准，便于演练历史时刻。

两版业务记录和取件字段见 [资料格式](source/formats.md)。`POST /control?edition=r2`
模拟业务方更换当期资料。来源语义、操作回执和演练档见[外部接口](source/provider.md)。

## 命令

| 命令 | 说明 |
| --- | --- |
| `sync` | 固定资料版取全部业务流，两校校历走增量或全量，回读 `offers`，复核承诺。`--full` 强制全量，`--edition r2` 固定版本，`--calendars false` / `--offers false` 跳过。 |
| `plan` | 输出每个课堂的窗口、接力、房间、释放与改约结论；`--format text` 给终端表格。 |
| `teacher` | 按某校本地日列出两个环节、哪边已有接通实据、仍待什么、通知何时真正发出。 |
| `hold <课>` | 申请校方暂留，`--by E,W` 限定学校（缺省两边）。重复调用复用已有凭据。 |
| `open <课>` | 用暂留凭据请校方开通。返回 202 只表示收到，结论以下一次回读为准。 |
| `confirm <课>` | 只有完整接力且两边有暂留/开通实据时，才发出请两边确认的通知。 |
| `amend <课> --by E` | 在确实出现房间关闭实据后安排更正，使用原通知号。 |
| `notify <课> --kind reschedule` | 把待发改约通知真正发给家长/学校，并记录送达时刻。 |
| `state` | 输出完整持久状态，便于排错。 |

## 判定规则

**窗口**：一节课要成立，必须同时满足

1. 两校各自的业务日历格覆盖整节课（`calendar` 按各自本地分钟解释，经 `tz` 换算成 UTC）；
2. 两校该课堂的会议室在课程时段 `open`；
3. 两校校历都公布并覆盖该课堂；
4. 不落在任何一校公布的禁止使用时段（`blocked-*`）内。禁止时窗按真实 UTC 时刻生效，
   跨零点的窗口会延续到真实结束时刻，因此也会压到另一地当地的课程上。

**口译接力**：主讲与问答各自独立指派，可以由不同人接。每人必须有对应语言方向、
可用时段覆盖该环节，且同一人不能在同一时段被两个班占用；环节共享边界可以接续。
只有两个环节都落实（完整接力）才允许请两边确认。未完整接力的课堂只保留建议，
不占住人员，避免一直挤占别班可用口译。

**资源占用顺序**：

- 已上完（`completed`）的课堂永远保留原资源，不进入重新择配，也不会因另一天的全量响应消失。
- 已有有效通知（`notified` 等）的课堂先占住原承诺，包括已发出的确认。
- 只有完整接力才允许请两边确认；确认通知真正送达后才计入占用。

**校历同步**：

- 完整响应带 `X-Scope`，只声明该站当地半开日期内的可用时窗；范围外的旧记录原样保留，
  不会因为一次全量响应而被悄悄删掉。
- 增量凭据过期（410，或演练档里没有对应增量路由）时重取完整新范围，并记入同步历史。
- 增量里的 `STATUS:CANCELLED` 只移除该 UID 的可用时窗；工具保留墓碑记录，视图里显示为
  「已取消」，任何择配都不会把它当作开放。另一天的全量不会删除范围外记录。
- 校历有效范围按记录的当地起始日解释；跨午夜的实际占用延续到真实结束时刻。

**房间关闭后要区分两件事**：

- 哪个时刻必须释放未开始的口译段：工具已知关闭时立即释放，最迟不得晚于该环节开始
  （输出里的 `releaseBy`）。已经开始的环节不被悄悄撤掉，交给联络员处理。
- 哪些课堂要改约：只有已经发出过确认/通知给两校或家长的课堂才进入改约队列，
  由联络员发出改约通知并记录真实送达时刻。尚未通知的课堂只标记为 `room-closed`。

本地释放记录优先于上游旧通知：来源里残留的旧签署不会让已释放的环节复活。

**会议室**：两边先各暂留，再分别接受。校方实际开通由 `offers` 回读确认；
已确认关闭的一侧不能再暂留或开通。更正只在某一地确实关闭后才允许，并使用原通知号。

## 结构

```
bin/liaison.mjs      命令行入口
src/config.mjs       配置与两校时区
src/time.mjs         内部分钟、本地墙钟、夏令时换算
src/ical.mjs         iCalendar 子集解析与 X-Scope
src/records.mjs      制表符记录解析
src/recordSource.mjs 业务流分页、资料版固定、ETag
src/provider.mjs     校历 / offers / hold / open / amend 客户端
src/sync.mjs         取数、校历全量与增量合并、回读
src/planner.mjs      窗口、接力指派、释放与改约判定
src/liaison.mjs      编排、通知日志、教师视图
src/render.mjs       终端表格
src/state.mjs        持久状态（临时文件 + rename）
```

## 边界

- 通知发送通过可替换的 `notifier` 实现（默认只在本地记录并返回回执）；
  接入真实邮件/短信前，`notify` 与 `confirm` 的送达时刻只代表本地记录时刻。
- 两校时区默认 `E`=`Asia/Shanghai`、`W`=`Australia/Melbourne`，可用 `--schools`
  （JSON）或环境变量覆盖。
